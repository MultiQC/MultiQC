# CLAUDE.md - MultiQC Plotly template

Guidance for the `plotly` report template, which renders plots with Plotly instead of the
default Apache ECharts engine. Selected via `multiqc --template plotly` (requires the
optional dependency, `pip install 'multiqc[plotly]'`).

## Thin child of `default`

This template is a child of `default` (`template_parent = "default"` in `__init__.py`). It
inherits every shared HTML file (`base.html`, `nav.html`, `head.html`, `includes.html`,
`footer.html`, `toolbox/*`, ...) from the default template and ships NONE of its own. The
only things it overrides are the plotting layer: its `src/js` Plotly renderer, the
`compiled/` bundle built from it, and the vendored Plotly asset under `assets/`.

The shared `default/includes.html` and `default/footer.html` switch the plot bundle and the
credit line on `config.plotting_engine`; this template sets `plotting_engine = "plotly"`, so
under `--template plotly` those inherited files load the Plotly bundle and Plotly credit.

For the shared frontend (HTML structure, SCSS, toolbox, build conventions), see
`multiqc/templates/default/CLAUDE.md`. Only the Plotly-specific pieces are covered here.

## Directory contents

```
multiqc/templates/plotly/
├── __init__.py       # template_parent = "default", plotting_engine = "plotly"
├── assets/           # Vendored Plotly bundle (base64-embedded into the report), images
├── compiled/         # ⚠️ AUTO-GENERATED by Vite - do not edit; committed and drift-checked in CI
├── src/js/           # Plotly rendering source: plotting.js (Plot base + renderPlot) + plots/*.js
├── package.json      # Node build deps and scripts
└── vite.config.js    # Vite bundler config (outputs to compiled/)
```

## Build

```bash
cd multiqc/templates/plotly
npm ci
npm run build        # bundles src/js -> compiled/ (also run automatically by prek hooks)
```

- NEVER edit `compiled/` directly; always edit `src/js` and rebuild.
- The committed `compiled/` output is drift-checked in CI (`.github/workflows/template_builds.yml`),
  alongside the default template, so rebuild and commit `compiled/` after any `src/js` change.
- The vendored Plotly bundle in `assets/js/packages/` is a committed file (no build script), not
  regenerated by `npm run build`.

## Testing changes

```bash
multiqc /path/to/test/data --template plotly --force
```

Open the generated `multiqc_report.html` and confirm plots render via Plotly
(`window.Plotly` is defined in the report).
